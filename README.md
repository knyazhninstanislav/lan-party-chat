<p align="center">

## 📖 О проекте

**LAN Party** - это лёгкий веб-чат, работающий **по локальной сети** без интернета и внешних зависимостей. Каждое сообщение — это отдельная **заявка** (тикет) с возможностью:

- 📝 писать многострочные сообщения;
- 📎 прикреплять файлы (документы, архивы, видео, аудио);
- 🖼️ вставлять скриншоты через `Ctrl+V` или drag-and-drop;
- ↩️ отвечать на конкретные заявки;
- ✏️ редактировать и 🗑️ удалять свои сообщения;
- ✅ помечать заявки как **выполненные**;
- 😊 вставлять эмодзи;
- 🔔 получать уведомления о новых заявках;
- 👀 видеть статус прочтения (`✅ прочитано N раз`);
- 🎨 **разноцветные градиентные аватарки**, автоматически привязанные к имени.

<img width="1031" height="654" alt="image" src="https://github.com/user-attachments/assets/4f0c17ff-38f4-4275-b297-6a7755426680" />


Сервер написан на **чистом Python** (стандартная библиотека), клиент — на **ванильном JavaScript**. Никаких фреймворков, сборщиков и `npm install`.
Это **не соцсеть**, не «убийца Slack» и не «наш ответ Telegram». Это **трещалка для узкого круга техсаппорта** — несколько человек, один офис, одна локальная сеть.

Задача была простая: **обмениваться заявками, скриншотами и «глянь, тут всё сломалось»** — без корпоративных мессенджеров, без VPN, без интернета, без «а давайте заведём Jira».

Отсюда все решения: минимум файлов, ноль зависимостей, работает на любой машине, где есть Python или докер. Пришёл, запустил, скинул ссылку коллегам — всё.

**Проект не претендует на:**

- масштабирование на тысячи пользователей;
- продакшен-надёжность;
- замену нормальных инструментов в большой компании;
- роль «социальной сети для всей организации».

**Он претендует ровно на одно** — чтобы **пятеро уставших саппортов** могли быстро перекинуться заявкой и не сойти с ума.

### Монолитный `main.js` — это осознанно

Весь клиентский код собран в **один файл** `main.js`, а не разбит на модули (`api.js`, `ui.js`, `state.js`, `attachments.js`).

**Почему так:**

- **Проект — про автономность.** Чем меньше файлов, тем проще раскатать чат на машину, у которой нет npm, сборщика и вообще ничего, кроме Python.
- **Никакой сборки.** Нет `webpack`, `vite`, `rollup`, `esbuild`. Файл кладётся рядом с `template.html` и работает.
- **Один запрос — один скрипт.** Браузер тянет один файл вместо пяти, нет каскадных загрузок и лишних round-trip'ов по локальной сети.
- **Проще таскать.** Скопировал папку — всё работает. Никаких `node_modules`, `package.json`, `dist/`.

## 🚀 Быстрый старт

### Требования

- **Python 3.7+** (используется только стандартная библиотека)
- Любой современный браузер
- Все устройства — **в одной локальной сети**

### Запуск сервера

```bash
python server.py
```

Сервер попробует порт из переменной `PORT`, иначе — `5555`. Если порт занят — сам подберёт свободный и напишет в консоль:

```
🔍 Используется порт: 5555
==================================================
🚀 Тикет-система запущена!
📱 http://localhost:5555
==================================================
🔒 Вход по паролю (регистрация + логин)
🛡️ Rate limit, сессии, WAL, индексы
⚡ Кэширование сообщений/юзеров/read-counts
==================================================
```

### Первый пользователь

Регистрации из браузера **нет** — пользователей создаёт админ:

```bash
python admin_tool.pyw
```

В админке: **Пользователи → Добавить пользователя**, задать имя и пароль (мин. 6 символов).

### Доступ с других устройств

1. Узнайте IP-адрес хоста:

   **Windows:**
   ```bash
   ipconfig
   ```
   Смотрите строку `IPv4-адрес` в активном подключении.

   **Linux / macOS:**
   ```bash
   ip addr
   # или
   ifconfig
   ```

2. На других устройствах откройте:

   ```
   http://<IP-хоста>:5555
   ```

   Например: `http://192.168.1.42:5555`

### Остановка

Нажмите `Ctrl+C` в терминале, где запущен сервер.

```bash
# Собрать и запустить в фоне
docker compose up -d
```

Открыть: **http://localhost:5555** (или порт, указанный в compose)

Остановить:

```bash
docker compose down
```

Остановить и **удалить БД** (сброс):

```bash
docker compose down -v
```

---

### 🚀 Запуск через `docker run` (без compose)

```bash
# Сборка образа
docker build -t lan-party .

# Запуск с сохранением БД в именованном томе
docker run -d \
    --name lan-party \
    -p 5555:5555 \
    -v lan-party-data:/app/data \
    lan-party
```

Остановить и удалить:

```bash
docker stop lan-party
docker rm lan-party
```

Удалить том с БД:

```bash
docker volume rm lan-party-data
```

Порт `5555` уже проброшен на хост. Убедитесь, что фаервол хоста разрешает входящие на `5555`.

# Контейнер запущен?

### 🐛 Если что-то не так

**Порт занят.** Поменяйте проброс в `docker-compose.yml`:

```yaml
ports:
  - "8080:5555"
```

Снаружи — `8080`, внутри — `5555`.

**Данные пропадают.** Проверьте, что том смонтирован:

```bash
docker inspect lan-party | grep -A 5 Mounts
```

Должен быть `lan-party-data` → `/app/data`.

**Healthcheck падает.** Увеличьте `--start-period` в `Dockerfile`:

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 ...
```

## 🖥️ Админ-панель (`admin_tool.pyw`)

Отдельное Tkinter-приложение, работающее **напрямую с `chat.db`** (тот же файл, что у сервера).

**Возможности:**

- 👤 Добавить пользователя (имя + пароль)
- 🔑 Сменить пароль (автоматически сбрасывает все сессии юзера)
- ✏️ Переименовать
- 🗑️ Удалить пользователя (каскадно: сообщения, вложения, прочтения)
- 🚪 Разлогинить (сброс всех сессий)
- 🧹 Очистить всю историю / историю выбранного юзера / старше N дней
- 🔎 Поиск по имени
- 📊 Колонки: имя, `user_id`, онлайн, дата создания, наличие пароля, кол-во сообщений

Запуск:

```bash
python admin_tool.pyw
```

> ⚠️ Tkinter в Python 3.7+ на некоторых сборках не поддерживает эмодзи вне BMP — поэтому в UI админки эмодзи намеренно убраны (см. `sanitize_for_tcl`).

## 🔐 Безопасность

| Механизм | Реализация |
|---|---|
| Хеширование паролей | PBKDF2-HMAC-SHA256, 200 000 итераций, уникальная соль |
| Сравнение хешей | `hmac.compare_digest` (защита от timing-атак) |
| Сессии | Случайный `token_urlsafe(32)`, TTL 24 ч, хранится в БД |
| Cookie | `HttpOnly; Path=/; SameSite=Strict; Max-Age=86400` |
| Rate limit | 5 попыток / 15 мин на IP, in-memory + аудит в `login_attempts` |
| Санитизация имени | Удаление control-символов и `< >`, лимит 20 символов |
| Санитизация файлов | `re.sub(r'[^\w.\-]', '_', ...)`, лимит 200 символов |
| Лимит тела запроса | 25 МБ |
| Лимит сообщения | 2000 символов |
| Лимит файла | 10 МБ, до 5 штук |
| Заголовки | `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store` |
| Gzip | Только если `Accept-Encoding: gzip` и тело > 1 КБ |

## ⚡ Производительность

- **SQLite WAL** — параллельное чтение при записи
- **`synchronous=NORMAL`** — быстрее без потери durability
- **Индексы** на `messages(created_at DESC, user_id)`, `attachments(message_id)`, `read_receipts(message_id)`, `users(last_seen DESC)`, `sessions(user_id, expires_at)`, `login_attempts(ip, attempted_at)`
- **Серверный кэш**:
  - `_messages_cache` — 1.0 с
  - `_users_cache` — 2.0 с
  - `_read_counts_cache` — 1.5 с
  - инвалидация при мутациях (`invalidate_messages/users/read_counts`)
- **ETag** на `/api/messages` — при отсутствии изменений сервер отвечает `304 Not Found`
- **Gzip** ответов > 1 КБ
- **Клиентский поллинг** — раз в 3 с (`loadMessages` + `updateUsersList` + `sendHeartbeat`)
- **Дедупликация `mark_read`** на клиенте (`markedReadIds` Set)

## 🔌 API — краткая справка

Все эндпоинты принимают и возвращают **JSON**. Авторизация — заголовок `Authorization: Bearer <token>` **или** cookie `session=<token>`.

### `GET` запросы

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/` | HTML-страница чата |
| `GET` | `/style.css` | Стили |
| `GET` | `/main.js` | Клиентский скрипт |
| `GET` | `/api/messages` | Список сообщений (с вложениями и `read_count`), поддерживает `If-None-Match` → `304` |
| `GET` | `/api/users` | Активные пользователи (`last_seen < 15 сек`) |
| `GET` | `/api/attachment/<id>` | Скачать/открыть вложение по ID |

### `POST` запросы

| Метод | Путь | Тело | Описание |
|---|---|---|---|
| `POST` | `/api/login` | `{username, password}` | Вход по паролю → `{token, username, user_id}` + `Set-Cookie` |
| `POST` | `/api/logout` | — | Выход: удаляет сессию, cookie, ставит `last_seen=0` |
| `POST` | `/api/send` | `{message, attachments[], reply_to?}` | Отправить новую заявку |
| `POST` | `/api/edit` | `{message_id, message}` | Редактировать своё сообщение |
| `POST` | `/api/delete` | `{message_id}` | Удалить своё сообщение |
| `POST` | `/api/toggle_completed` | `{message_id}` | Переключить статус «Выполнено» |
| `POST` | `/api/mark_read` | `{message_id}` | Отметить сообщение прочитанным |
| `POST` | `/api/heartbeat` | — | Продлить сессию (онлайн) |

> ℹ️ Регистрации через API **нет** — только через `admin_tool.pyw`.

## 🗄️ База данных

SQLite, файл `chat.db` создаётся автоматически при первом запуске. Включены `WAL`, `foreign_keys=ON`, `synchronous=NORMAL`.

### Таблицы

**`users`** — пользователи

| Поле | Тип | Описание |
|---|---|---|
| `user_id` | TEXT (PK) | Уникальный ID |
| `username` | TEXT UNIQUE | Отображаемое имя |
| `password_hash` | TEXT | PBKDF2-SHA256 hex |
| `salt` | TEXT | Уникальная соль |
| `last_seen` | REAL | Timestamp последней активности |
| `created_at` | REAL | Дата регистрации |

**`sessions`** — сессии

| Поле | Тип | Описание |
|---|---|---|
| `token` | TEXT (PK) | Случайный токен |
| `user_id` | TEXT | FK на `users` (CASCADE) |
| `expires_at` | REAL | Время истечения |
| `ip` | TEXT | IP, с которого создана |
| `created_at` | REAL | Timestamp создания |

**`messages`** — сообщения-заявки

| Поле | Тип | Описание |
|---|---|---|
| `id` | TEXT (PK) | Уникальный ID |
| `username` | TEXT | Автор |
| `user_id` | TEXT | FK на `users` |
| `message` | TEXT | Текст заявки |
| `timestamp` | TEXT | Время (`HH:MM:SS`) |
| `edited` | INTEGER | `1`, если редактировалось |
| `edit_time` | TEXT | Время правки |
| `reply_to` | TEXT | ID родительского сообщения |
| `completed` | INTEGER | `1`, если выполнено |
| `created_at` | REAL | Timestamp создания |

**`attachments`** — вложения

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER (PK) | ID файла |
| `message_id` | TEXT | FK на `messages` (CASCADE) |
| `filename` | TEXT | Имя файла |
| `file_data` | TEXT | Содержимое в base64 |
| `file_type` | TEXT | MIME-тип |
| `file_size` | INTEGER | Размер в байтах |

**`read_receipts`** — прочтения

| Поле | Тип | Описание |
|---|---|---|
| `message_id` | TEXT | FK на `messages` |
| `user_id` | TEXT | FK на `users` |
| `read_at` | REAL | Timestamp |

**`login_attempts`** — аудит логинов

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER (PK) | ID записи |
| `ip` | TEXT | IP |
| `username` | TEXT | Имя (если было) |
| `success` | INTEGER | `1`/`0` |
| `attempted_at` | REAL | Timestamp |

### Сброс БД

Просто удалите `chat.db`.

## 🧭 Как пользоваться

1. **Получить аккаунт** — попросите админа создать вас через `admin_tool.pyw`.
2. **Вход** — введите имя и пароль в поле сверху, нажмите «Войти».
3. **Создание заявки** — напишите текст, при необходимости прикрепите файлы, нажмите «Отправить» (или `Enter`).

5. **Ответ на заявку** — нажмите «Ответить» под нужной карточкой.
6. **Отметить выполненной** — кнопка «✓ Выполнено».
7. **Редактирование/удаление** — доступно только автору.
8. **Вставка скриншота** — `Ctrl+V` прямо в поле ввода.
9. **Drag-and-drop** — перетащите файлы в окно чата.
10. **Выход** — кнопка «🚪 Выйти» в правом верхнем углу.

## 🔧 Решение проблем

### Порт занят

Сервер сам подберёт свободный. Если нужно зафиксировать — задайте `PORT`:

```bash
PORT=8080 python server.py
```

Или найдите в `server.py`:

```python
PORT = int(os.environ.get('PORT', 0))
if not PORT:
    PORT = find_free_port()
```

### Другие устройства не подключаются

- Убедитесь, что все в одной сети.
- Проверьте фаервол — разрешите входящие на порт `5555` (или выбранный).
- Windows: добавьте правило в «Брандмауэр Защитника».

### Не отображаются картинки/файлы

- Файлы хранятся в БД в base64 — большие вложения могут замедлить загрузку.
- Уменьшите `MAX_FILE_SIZE`.

### «Сессия истекла» / «Не авторизован»

- TTL сессии — 24 часа.
- Админ мог нажать «Разлогинить» в `admin_tool.pyw`.
- Смена пароля автоматически сбрасывает все сессии пользователя.
- Войдите заново.

### «Слишком много попыток. Подождите 15 минут»

- Сработал rate limit: 5 неудачных логинов с одного IP за 15 минут.
- Подождите или перезапустите сервер (in-memory счётчик сбросится; аудит в БД останется).

### Не запускается `admin_tool.pyw`

Нужен `tkinter`:

- **Linux:** `sudo apt install python3-tk`
- **Windows:** переустановить Python с компонентом Tcl/Tk
- **macOS:** `brew install python-tk`
